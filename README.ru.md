# asd-ste100-ru — упрощённый технический русский

Навык для агентов. Переписывает плотный и неоднозначный русский текст по правилам, перенесённым из [ASD-STE100](https://www.asd-ste100.org/) (Simplified Technical English). Основан на английском навыке [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill) (MIT).

ASD-STE100 описывает только английский язык. Этот навык — адаптация, а не официальный стандарт. Для английского текста используй навык `asd-ste100`.

## Что изменено для русского языка

- Лимиты длины: ≤18 слов для инструкций, ≤22 слова для описаний. Тире не считается словом.
- Вместо запрета перфекта — правила о виде глагола и составных формах.
- Вместо фразовых глаголов — жаргонные кальки: «пофиксить», «заапрувить», «задеплоить».
- Вместо цепочек существительных — цепочки родительного падежа.
- Новые правила: канцелярит, прямой порядок слов, причастные и деепричастные обороты, однозначные местоимения, двойное отрицание, идентификаторы в обратных кавычках.
- Раздел о собственных ответах агента: навык применяется при написании, а не только при правке.

## Установка

Подробная инструкция и готовый промпт для установки через ИИ-агента — в [README.md](README.md#installation). Коротко:

```bash
git clone https://github.com/wh1tespirit/asd-ste100-ru.git ~/.agents/skills/asd-ste100-ru
ln -s ~/.agents/skills/asd-ste100-ru ~/.claude/skills/asd-ste100-ru   # Claude Code
```

Codex CLI и OpenCode читают `~/.agents/skills/` сами. Hermes Agent: ссылка в `~/.hermes/skills/writing/`. Чтобы агент всегда отвечал по навыку, добавь в `AGENTS.md` или `CLAUDE.md` строку: «Для ответов на русском всегда используй навык asd-ste100-ru».

## Файлы

- `SKILL.md` — правила, режимы, порядок работы и формат вывода.
- `references/writing-rules.md` — разделы STE, русская адаптация и источники.
- `examples/before-after.md` — примеры «до/после».
- `scripts/ste-lint.py` — линтер структурных правил на стандартной библиотеке Python.

## Линтер

```bash
python3 scripts/ste-lint.py --selftest
python3 scripts/ste-lint.py docs/README.md
echo "Выполните проверку конфигурации." | python3 scripts/ste-lint.py --json
python3 scripts/ste-lint.py examples/linter-edge-cases.md   # ожидаются 2 находки
```

Жёсткие правила: `semicolon`, `long-sentence`, `jargon-verb`, `marketing-adjective`, `bureaucratese`, `nominalization`, `synonym-rotation`, `dangling-conjunction`. Рекомендательные правила: `passive-voice`, `verbose-copula`, `double-negation`. Линтер использует регулярные выражения без морфологического анализа. Он не проверяет порядок слов, цепочки родительного падежа, обороты и местоимения. Модальность линтер не отмечает никогда.

Нулевой результат означает только одно: настроенные структурные проверки не нашли проблем. Линтер не сравнивает исходный текст с правкой и не доказывает, что смысл сохранён.

Собственная проза навыка не проходит линтер без находок: таблицы цитируют запрещённые образцы. Проверяй так: `python3 scripts/ste-lint.py --baseline 40 SKILL.md`. Читай находки как примеры, а не как дефекты.
